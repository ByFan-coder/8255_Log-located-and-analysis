# 简短 Bug 表单与本地去重

用于日志分析时记录关键信息、识别同一事件和关联相似问题。只做本地辅助判断，不代替缺陷系统或根因验证。

## 保存范围

默认用当前分析目录的 `bug_table.md` 作为持久索引；不存在时从技能的 `assets/bug_table.md` 复制空白模板，再记录实际分析结果。用户已指定本地 Bug 表时使用该表，不另造重复索引；更换格式前先适配已有内容，不覆盖旧记录。

只比较当前索引及用户已提供/明确指定的历史材料，不自动扫描其他项目、聊天或上传内容。不同日志目录之间只有共享同一索引或明确提供历史表时才可去重；初次空表不能声称查遍历史。先确认故障时间与覆盖，再初查索引；分析后复核并记录结果。

## 简短表单（每次分析）

```text
Bug ID：用户已有编号；没有则生成本地编号
项目/版本：项目、系统/BSP版本；未知则标待确认
故障对象与现象：哪块屏/哪个模块，发生什么
发生时间/启动实例：故障日期时间或候选窗口、boot/设备标识（已知时）
关键特征与证据：失败层/函数/错误类型或关键事件链，附原始日志定位
简要结论/建议模块：当前定位及不确定性，不把假设写成确认根因
去重结果/关联ID：结果、关联Bug及一句依据
```

表单是索引行的填写口径，不要求在聊天重复完整展示。完整分析沿用原报告，非驱动/非屏端仍保持简析；缺的信息写“未知/待确认”，不为补齐表单反复询问无关字段。

新建本地编号可用 `BUG-YYYYMMDD-001`，日期取记录日期，按索引当日最大序号递增；用户已有缺陷编号则保留。未知故障日期不能拿编号日期替代。补日志或同事件复核时复用原ID；独立发生的新事件新增记录并关联候选。编辑前重读索引防止覆盖其他新增行；不能安全合并时保留原文并说明待补记。

## 简单去重规则

1. **筛候选：**先比较项目、故障对象、现象及场景，再核对版本、关键特征和时间/启动。表中的关键特征用稳定的错误类型、函数/等待点、通路、协议命令及事件顺序；变化的PID、时间戳、随机句柄不作为跨事件特征。不同系统的错误码不可脱离各自语义比较。
2. **重复（同一事件）：**有依据确认同一设备/启动、同一故障窗口、同一故障链，或同一事件的相同原始日志与新增附件。更新旧记录、复用ID，补新文件和结论变化；同一个日志包内不同现象仍可能是不同Bug。
3. **疑似重复：**不同事件具有相近场景、对象和特征，但未确认同一根因，或版本/时间/设备信息不足。保留独立记录，关联候选ID并说明匹配点与待确认差异。即使机制已确认相同，独立复现也保留发生记录；需要合并缺陷单时交用户决定。
4. **未发现重复（限当前索引）：**本次已与当前历史索引比较，但未找到匹配候选；空表同样限定范围，不能推断整个项目没有重复。
5. **无法判断：**关键材料不足或历史表不可读/未提供，说明缺项；不能因缺证据强行标新Bug或重复。

“黑屏”“ANR”“I²C无ACK”“timeout”这种通用现象/关键词单独相同不足以判重；不同物理屏、协议、版本、启动以及故障时间的差异不能被忽略。项目/版本未知不能视为与任意历史记录一致。去重不改变日志覆盖限制，不以旧结论替代本次定位，不自动归责、删行、合并或关闭Bug。

## 索引填写与回复

每行记录一个独立故障事件或一个尚待区分的问题。证据给可点击的原始文件与编辑器行号，长报告可另给链接；不将整段日志或源码塞进表格。Markdown单元格中的 `|` 要转义，换行用简短分句，避免破坏表结构。时间/版本修正和结论变化补一句说明，不静默覆盖已知不同事实。

最终回复增加一行，例如“Bug记录：本地ID；疑似重复，关联已有ID（共同特征，差异待确认）”，并链接实际 `bug_table.md`。这行放在屏幕信息或建议流转模块之前，保留原有输出规则。记录无法写入时明确说明未保存，不能宣称已登记。
