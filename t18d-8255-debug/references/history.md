# 历史案例经验与证据边界

以下是从历史调试经验抽象出的查证方法，不包含原始日志或现场证据。不同版本、屏型、Host/Guest 架构均需在当前材料中重新核实；不能直接套用历史结论。

| 案例类型 | 可复用的经验 |
|---|---|
| 触摸停止上报 | Android 输入记录不能替代 QNX 层证据；检查 DSV_PKMS 魔数，截断包需记录覆盖限制。 |
| 多指状态残留 | 对比原始帧、解析结果和发送状态，先确认 ID 是稳定身份还是本帧序号；快照和增量协议不能采用同一清理逻辑。 |
| 仪表黑屏 | 主 HMI 和安全层分别检查；整机空闲不等于图形专用池可用，需看分进程占用与分配需求。 |
| 背光通信失败 | 主机调用结果不等于屏端实际状态；无 ACK 可能涉及线束、供电、复位、地址或透传配置。 |
| 红条或局部异常 | FPS、CRC、主机存活不能证明实体画面正确；人工重启与故障触发分开，不能排除屏端局部掉电。 |
| 初始化证明 | 运行刷新日志不能替代直接的初始化成功证据，需要对应屏的端口、链路及 SER/DES 配置记录。 |
| 图形超时 | 建通道超时与运行期 timeline 等待超时分开；跨层打印可能是同一次失败，调用方不一定是触发方。 |
| 内核等待 | 不混 boot；等待者不等于持锁者，pending work 不等于正在执行，高 CPU 与阻塞线程按 TID 分别查。 |
| 无焦点 ANR | onResume 返回不等于窗口就绪；缺全栈时不凭两个等待点拼接线程依赖。 |
| 寄存器访问异常 | UART 与 Android 墙钟对齐不等于 Host/Guest 对齐；虚拟地址与物理映射分开，不能用故障后清理倒推故障前撤销。 |

这些经验用于选择检索和验证路径。实际结论必须附当前材料的时间、启动实例、覆盖范围和编辑器行号；未验证假设明确标注。
